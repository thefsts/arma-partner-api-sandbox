## 4. What shipped

`certification/` is the deterministic, fail-closed integration certification reporter per the owner-approved proposal in `docs/STOP-POINT-9-REPORT.md` §10. It consumes the evidence of every test lane into one owner-readable report — what is PASS, what is FAIL, what was NOT TESTED, per requirement and per category, with safe reason codes and metadata-only evidence references — and never reports PASS for an untested requirement.

- **`certification/certify.ts`** — the engine. (a) TAP lane parser: reads node:test's real output shapes — subtest headers, passing and failing YAML blocks (multi-line `error:`/`expected:`/`actual:`/`stack:` detail discarded, never retained), TAP-escaped names (`\#`, `\\`) unescaped exactly once, cancelled rows via the YAML `failureType` field, file-level load failures via the YAML `exitCode` field; parse-level diagnostics (`TAP_*`) are recorded but never used as row reason codes. (b) Row coercion: the SP8 `CertificationRow { testId, category, requirement, result, reasonCode }` plus the metadata-only `sourceFile`; unknown fields dropped, unknown result values degraded to NOT-TESTED, PASS without a reason code is not-understood evidence (NOT-TESTED), unsafe or oversized codes degrade — never a fabricated PASS. (c) Duplicate resolution: identical duplicates → one NOT-TESTED row (`ROW_DUPLICATE_IDENTICAL`); divergent rows (same testId, different results) → FAIL (`ROW_CONFLICTING_EVIDENCE`). (d) Lane collapse with a root-cause priority chain (`LANE_COLLAPSE_PRIORITY`: LANE_OUTPUT_EMPTY, LANE_MALFORMED_OUTPUT, LANE_COUNT_MISMATCH, LANE_UNCOLLECTABLE, LANE_EMPTY): a lane whose declared count drifts, whose runner dies outside its tests, whose output is empty or malformed collapses to NOT-TESTED; PASS rows in a collapsed lane are withheld (`LANE_COLLAPSE_PASS_WITHHELD`) while genuine FAIL rows stay FAIL — never buried. (e) Deterministic assembly: canonical sort, input-order lanes, name-sorted categories, no timestamps. (f) `renderReportHtml`: self-contained static page — inline CSS, zero scripts, zero external assets, attention section first. (g) `verifyReport`: closed key sets, totals arithmetic, category and lane arithmetic, canonical-ordering and uniqueness invariants. (h) `assertMetadataOnly`: the forbidden-material leak sweep with surface-label-only throws (the throw never carries the material).
- **`scripts/generate-certification-report.mjs`** — the driver: the committed manifest declares every one of the 33 test files with its category and declared count (empirically derived by parsing each file's real TAP with the real engine — never assumed); every declared file runs as its own TAP lane (`node --test --test-reporter=tap <file>`, maxBuffer 64 MiB, 240s timeout); the SP8 contract matrix (`runContractMatrix()`) is imported in-process and coerced row-by-row; a sweep over all seven test directories collapses any on-disk test file the manifest does not declare (`LANE_UNDECLARED`) — no silent skips anywhere; self-verification + JSON round-trip verification + leak sweep run BEFORE the artifacts are written; prints per-lane state, an attention section for every non-PASS row, and totals; exit 0 on a failing/non-certified record (the reporter records; the lanes gate) — non-zero exit reserved for reporter-internal defects.
- **`scripts/verify-certification-report.mjs`** — the committed-artifact verifier for CI: JSON parse + full invariant verification, HTML must be byte-identical to `renderReportHtml(report)` (lockstep with the JSON), the same 15-fixture leak sweep; prints violation codes only; exit 1 on any violation.
- **`certification/tests/`** — the 66-test lane: the positive lane (30) exercises real-shaped TAP parsing, row mapping and coercion, lane collection, duplicate/conflict resolution, deterministic assembly, the SP8 matrix coercion, self-contained HTML rendering, sweep semantics, and the closed vocabularies; the negative lane (36) proves the never-PASS invariant across every fail-closed path — empty/malformed/missing lanes, count drift, crashed runners, skip/todo/cancelled directives, unknown fields/results/codes, identical and conflicting duplicates, PASS-withholding under collapse, leak injection with surface-label-only throws, and ten tamper mutations the verifier must catch.
- **CI wiring** — three additive steps after the test step: `pnpm certify:generate` (records, does not gate), the lockstep check (`git diff --exit-code -- docs/certification/` — the regenerated artifact must be byte-identical to the committed one, proving the report is in lockstep with the tree), and `pnpm certify:verify` (the integrity gate).
- **`docs/certification/`** — the committed artifacts (JSON + HTML) so the owner can read the exact certified state of the sandbox at any commit without running anything.
