## 4. What shipped

`certification/` is the deterministic, fail-closed integration certification reporter per the owner-approved proposal in `docs/STOP-POINT-9-REPORT.md` §10. It consumes the evidence of every test lane into one owner-readable report — what is PASS, what is FAIL, what was NOT TESTED, per requirement and per category, with safe reason codes and metadata-only evidence references — and never reports PASS for an untested requirement.

- **`certification/certify.ts`** — the engine. (a) TAP lane parser: reads node:test's real output shapes — subtest headers, passing and failing YAML blocks (multi-line `error:`/`expected:`/`actual:`/`stack:` detail discarded, never retained), TAP-escaped names (`\#`, `\\`) unescaped exactly once, cancelled rows via the YAML `failureType` field, file-level load failures via the YAML `exitCode` field; parse-level diagnostics (`TAP_*`) are recorded but never used as row reason codes. (b) Row coercion: the SP8 `CertificationRow { testId, category, requirement, result, reasonCode }` plus the metadata-only `sourceFile`; unknown fields dropped, unknown result values degraded to NOT-TESTED, PASS without a reason code is not-understood evidence (NOT-TESTED), unsafe or oversized codes degrade — never a fabricated PASS. (c) Duplicate resolution: identical duplicates → one NOT-TESTED row (`ROW_DUPLICATE_IDENTICAL`); divergent rows (same testId, different results) → FAIL (`ROW_CONFLICTING_EVIDENCE`). (d) Lane collapse with a root-cause priority chain (`LANE_COLLAPSE_PRIORITY`: LANE_OUTPUT_EMPTY, LANE_MALFORMED_OUTPUT, LANE_COUNT_MISMATCH, LANE_UNCOLLECTABLE, LANE_EMPTY): a lane whose declared count drifts, whose runner dies outside its tests, whose output is empty or malformed collapses to NOT-TESTED; PASS rows in a collapsed lane are withheld (`LANE_COLLAPSE_PASS_WITHHELD`) while genuine FAIL rows stay FAIL — never buried. (e) Deterministic assembly: canonical sort, input-order lanes, name-sorted categories, no timestamps. (f) `renderReportHtml`: self-contained static page — inline CSS, zero scripts, zero external assets, attention section first. (g) `verifyReport`: closed key sets, totals arithmetic, category and lane arithmetic, canonical-ordering and uniqueness invariants. (h) `assertMetadataOnly`: the forbidden-material leak sweep with surface-label-only throws (the throw never carries the material).
- **`scripts/generate-certification-report.mjs`** — the driver: the committed manifest declares every one of the 33 test files with its category and declared count (empirically derived by parsing each file's real TAP with the real engine — never assumed); every declared file runs as its own TAP lane (`node --test --test-reporter=tap <file>`, maxBuffer 64 MiB, 240s timeout); the SP8 contract matrix (`runContractMatrix()`) is imported in-process and coerced row-by-row; a sweep over all seven test directories collapses any on-disk test file the manifest does not declare (`LANE_UNDECLARED`) — no silent skips anywhere; self-verification + JSON round-trip verification + leak sweep run BEFORE the artifacts are written; prints per-lane state, an attention section for every non-PASS row, and totals; exit 0 on a failing/non-certified record (the reporter records; the lanes gate) — non-zero exit reserved for reporter-internal defects.
- **`scripts/verify-certification-report.mjs`** — the committed-artifact verifier for CI: JSON parse + full invariant verification, HTML must be byte-identical to `renderReportHtml(report)` (lockstep with the JSON), the same 15-fixture leak sweep; prints violation codes only; exit 1 on any violation.
- **`certification/tests/`** — the 66-test lane: the positive lane (30) exercises real-shaped TAP parsing, row mapping and coercion, lane collection, duplicate/conflict resolution, deterministic assembly, the SP8 matrix coercion, self-contained HTML rendering, sweep semantics, and the closed vocabularies; the negative lane (36) proves the never-PASS invariant across every fail-closed path — empty/malformed/missing lanes, count drift, crashed runners, skip/todo/cancelled directives, unknown fields/results/codes, identical and conflicting duplicates, PASS-withholding under collapse, leak injection with surface-label-only throws, and ten tamper mutations the verifier must catch.
- **CI wiring** — three additive steps after the test step: `pnpm certify:generate` (records, does not gate), the lockstep check (`git diff --exit-code -- docs/certification/` — the regenerated artifact must be byte-identical to the committed one, proving the report is in lockstep with the tree), and `pnpm certify:verify` (the integrity gate).
- **`docs/certification/`** — the committed artifacts (JSON + HTML) so the owner can read the exact certified state of the sandbox at any commit without running anything.

## 6. Red-gate incident record (ERROR RULE honored — root cause re-diagnosed and fixed; corrected)

During the final-gate sequence on the committed tree, the lockstep step exited 1: the regenerated report showed the `law-shield/tests/arma.transfer.test.mjs` lane collapsed (1 FAIL + 13 PASS-withheld, `LANE_MALFORMED_OUTPUT`) — contradicting the 539/539 suite result minutes earlier and the two all-green pre-commit generation runs. STOP → diagnose → fix → rerun. **The original root-cause attribution in the first publication of this report (a "load collision" with an orphaned overlapping suite process) was WRONG; this section records the corrected, empirically proven diagnosis and the fix that shipped in commit `f505944`.**

1. **First-pass diagnosis (superseded):** solo lane rerun 14/14 GREEN; deterministic engine probes (thrown-Error and assertion-failure TAP shapes through the real `collectLane`) produced correct FAIL rows with no collapse; zero `console.*` noise in law-shield; a concurrent orphaned full-suite process existed at that moment. That pointed to a load collision, and a clean sequential rerun went all-green — which looked like confirmation but was in fact the flake passing, as later proven below.
2. **Re-opened at close-out — the flake reproduces SOLO:** a zero-load solo rerun loop of the lane produced `tests 15 / pass 13 / fail 1` with the identical lane collapse, and the failing test was the SAME one named in the preserved red-gate evidence: `invalid receipt signature (200 with tampered receipt) fails closed to reconciliation`, expecting `RECONCILIATION_REQUIRED` but getting `ACCEPTED`. A genuinely failing lane that emits a failure after its final ✔ lines, followed by the process hanging, is precisely the TAP shape the red gate captured — the "load collision" theory could not produce this solo, and the red evidence's FAIL row had named this test all along.
3. **True root cause (proven empirically):** the test's signature tamper `v.replace(/./, 'f')` replaces the FIRST hex character of the 64-char HMAC signature with `'f'` — a **no-op whenever the first character is already `'f'`**. A 200-send probe through the exact test stack measured the first-char distribution: uniform over `0-9a-f`, with `'f'` at 12/200 ≈ 1/16. On a no-op send the tampered receipt still verifies, the transfer becomes `ACCEPTED`, the assertion fails, and the test throws. The identical pattern existed in `processor.durable.test.mjs` (test 18).
4. **The cascade that made it a lane collapse:** `cleanup(h)` (gateway + processor `server.close()`) only runs at the end of a test body, so the thrown assertion skipped it — the child's two listener handles pinned the event loop and the test child hung indefinitely (`--test-timeout=0` in the suite runner), producing the truncated/never-finalized TAP stream the reporter saw. A dedicated handle probe proved the mechanism: with cleanup skipped the process hangs with 2 Server handles; with `unref()` on the listeners the handle list drains and the process exits 0. This cascade was latent in every law-shield/openapi lane that boots its own listener.
5. **Fix (commit `f505944`, single correction commit):** (a) deterministic tamper in both affected tests — map the first hex char to a guaranteed-different char (`'f' → '0'`, anything else `→ 'f'`), validated by 60/60 and 40/40 solo loop passes on the two tests; (b) `unref()` on every synthetic test listener across `law-shield/tests/helpers/servers.mjs` and the four lanes that boot their own servers (`arma.transfer`, `processor.durable`, `e2e.synthetic`, `openapi/spec.live-conformance`) so a skipped or failed teardown can never again pin the event loop — the full 539 suite now completes in ~5 seconds with zero stalls; (c) `package.json`: the `test` script was missing the `certification/tests/**/*.test.mjs` glob, so CI's `pnpm test` step was running 473 tests, not the published 539 — the glob was added so `pnpm test` truly runs all 539 (certification tests were already exercised in CI via the `certify:generate` lanes, but the test-step total and the report/README claims now match reality).
6. **What the reporter proved under real conditions:** the fail-closed invariant worked exactly as designed — on a genuinely failing, hung lane it withheld all 13 PASS rows, kept the real FAIL row visible, collapsed the lane with a typed code (`LANE_MALFORMED_OUTPUT` / `LANE_COLLAPSE_PASS_WITHHELD`), and never fabricated a PASS on damaged evidence. The incident is a live demonstration of the SP10 invariant — and of why an owner-facing certification report must be fail-closed, because the underlying test flake it surfaced was real and is now fixed.
7. **Final rerun on the corrected tree:** all six gates GREEN (typecheck exit 0; 539/539; generate 662 PASS with self-verify + leak sweep OK; lockstep exit 0 with SHA-256 match on both artifacts; verify exit 0; secret scan clean). The red evidence was preserved and nothing was shipped from it.
